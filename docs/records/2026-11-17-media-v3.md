## 1. 阶段 0 底座重构与缺陷排查

在出片采集前，针对原型文件 `prototype/team-kanban-prototype.html` 与测试套件完成关键修复与验证：

1. **FLIP 换列落点越界修复**：
   - 修复 `.tkb-flights` 飞行卡片容器绝对定位样式（`position: absolute; inset: 0; pointer-events: none`），避免飞行容器因相对位置偏差将卡片投射至 lane 底部空白裁切区。
   - 所有移动卡片目标矩形严格受限于 target lane 内，边界断言 `to.y + to.h <= laneBody.bottom + 2` 100% 通过。
2. **Crowd 守卫与错峰**：
   - 飞行卡片阈值提升为 `> 12`，在多任务并发时按 `idx * ms(30)` 施加级联错峰，杜绝多卡同帧瞬移与画面突变。
3. **采集用 URL 注入**：
   - 增加 `?embed=1`、`?speed=8`、`?theme=light|dark`、`?script=loop`、`?gaze=1` 等参数化钩子，暴露全局只读句柄 `window.__TKB`。
4. **单元测试验证**：
   - 全套 39 项单元测试（涵盖 DAG 解析、会话状态投影、归一化、DOM 响应）全部通过（`npm test` 39/39 passing）。

## 2. A 线：README 循环图 (`kanban-loop-v3.webp`)

### 采集与编码参数
- **分辨率**: 900 × 1000（1:1 像素，针对 GitHub README 白底设计，只裁不缩）
- **主题**: Light 浅色模式（平均亮度 Luma 230.4，告别深色黑洞与模糊压缩）
- **帧率与时长**: 20.00 fps，8.00 秒（共 160 帧）
- **母板慢放采集**: 8× 慢放 + 10fps 无头采集（每成片秒对应 80 真实采样帧），经 Lanczos 缩放后由 `img2webp -loop 0 -mixed -q 68 -m 6 -d 50` 封装。
- **动态编排**: 11 步高频微动作，涵盖待处理落入、依赖解锁、跨列 FLIP 飞行、环形角标打勾（4/6 → 6/6）及末尾 0.35s 柔和淡出回首帧。

## 3. B 线：发布宣传片 (`kanban-launch-v3.mp4`)

### 制作与编排规格
- **规格**: 1920 × 1080 @ 60.00 fps，18.00 秒（共 1080 帧无插值真 60fps）
- **渲染引擎**: 2.5D PageCam 原型运镜播放器 (`media/launch/player.html`)，通过 Playwright 驱动 Chrome 无头管线逐帧直推 ffmpeg。
- **分镜结构**:
  - Shot 1 (0.0s–3.0s): 1080P 全景平移推镜，展现左侧多智能体对话与右侧看板共生结构。
  - Shot 2 (3.0s–6.5s): 2.5D 深度运镜聚焦右侧栏「待处理」列与依赖阻塞标记。
  - Shot 3 (6.5s–10.5s): FLIP 物理抛物线跨列流转微距特写。
  - Shot 4 (10.5s–13.5s): 任务全清状态，顶部全满能量条与标签页 6/6 打勾环形角标特写。
  - Shot 5 (13.5s–15.5s): 动态卷帘对比浅色（Light）与深色（Dark）模式自适应跟随。
  - Shot 6 (15.5s–18.0s): 一键收队确认浮层柔和拉远，平滑过渡至品牌卡片收尾定格。
- **音频系统**: 混音 120BPM Tech-House 现代极简音轨，严格对齐 5 处 UI 动作音效（Woosh、Select、Success、Switch、Impact），真峰值 ≤ -1.0 dBFS。附带交付纯净无 BGM 版供二次剪辑。
