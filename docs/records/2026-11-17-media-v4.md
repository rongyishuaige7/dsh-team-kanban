# 2026-11-17 · media-v4 发布片重制

## 背景

v3 是 4 张静态 PNG 加手写 CSS transform 拼出来的：`media/launch/player.html` 用 442 行自研"运镜"
顶替了 video-shotcraft 的 PageCam，`shot2`/`shot3` 从未生产。它自报"全部 PASS"，是因为当时
`tools/audit/media-metrics.mjs` 只测像素变化量——静态图推镜就能刷满。本次连同门槛一起重做，
v3 资产与工程已删除（见 git 历史）。

## 做法

- 引擎换成 **Remotion 4.0.484**，组件为自建的 2.5D `Scene`（真实截图/视频 + 相机关键帧）
- 素材改为**真实运行的 60fps 采集**：页面 5× 慢放 + 45ms 间隔截图（JPEG q95）+ 按时间戳重采样到 60fps
- 飞行镜头单独用 **20× 慢放**重拍，0.5× 播放后仍有 148 帧/秒有效帧
- 停用团队一镜使用**真实鼠标操作**并记录轨迹，在 Remotion 里按页面坐标重绘光标与点击涟漪

## 一并修掉的缺陷

原型 `setTimeout(startPlay, 900)` 与 `?play=1` 会形成两条并行时间线，把脚本推进成双倍速——
这正是 v2/v3 时间轴对不上的根因，已在原型中加 `?play` 守卫。

## 门槛的教训

重写门槛时先验证它能不能识别 v3，结果发现：**「稳像后残差」抓得住纯平移推镜，抓不住
「4 张静态图 + 硬切 + 缩放」**——v3 在这项上反而有 69%，因为 vidstab 只建模平移与旋转，
不建模缩放和切镜。

所以真正的判据是**出处清单**：`media/launch-v4/timeline.json` 逐镜声明 `kind: live|still`，
`media-metrics.mjs --manifest` 要求 live 占比 ≥50%（v4 实测 83.3%）。像素指标只作为辅助，
用来查重复帧、亮度、单帧 ΔLuma 这类硬缺陷。

教训：验收指标必须先在已知坏样本上跑一遍，能挂掉才算数。
